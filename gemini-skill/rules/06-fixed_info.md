# お礼メールの固定情報

# 固定情報

毎回同じ値を使うもの。議事録から拾わなくてよい。
ただし議事録で別の値が明言されていた場合は議事録を優先する。

## 担当者情報（使う人ごとに変わる）

**このスキルは複数の営業担当が使う。** 以下は使う人によって変わるため、
スキル内に固定値を持たない。

| 項目 | 用途 |
|---|---|
| 担当者の名字 | 件名・冒頭の名乗り・署名 |
| Zoom URL | 次回打ち合わせブロック |
| ミーティングID | 次回打ち合わせブロック |

**初回の使用時、これらが不明なら必ず本人に聞く。**
推測で埋めたり、他の担当者の情報を使ったりしない。

```
お礼メールを作る前に、以下を教えてください。

・お名前（名字のみで大丈夫です）
・ZoomのURL
・ミーティングID

次回からは会話の中で覚えておきますので、毎回聞くことはありません。
```

会話の中ですでに担当者名やZoom情報が出ていれば、それを使う。
次回打ち合わせが設定されていない回であれば、Zoom情報は聞かなくてよい。

## 件名

```
本日はありがとうございました（ネオキャリア・[担当者名]）
```

受注後（型D）のみ：

```
このたびはありがとうございました（ネオキャリア・[担当者名]）
```

資料送付（型F）は、送るものが分かる件名にする：

```
ご提案資料のご送付（ネオキャリア・[担当者名]）
お見積書のご送付（ネオキャリア・[担当者名]）
```

## 宛名

```
[会社名]
[担当者名]様
```

**原則、商談に参加した全員の名前を入れる。** 複数名は全角スペース区切りで1行に並べる。
順番は役職が上の人から。役職が分からない場合は、商談で先に発言した人・議事録に多く登場する人を先に置く。

```
株式会社モノリスソフト
関口様　山根様
```

**例外：相手からのメールへの返信として送る場合は、差出人1名のみを宛名にする。**
（例：商談後に担当者からデータが送られてきて、それに返信する形でお礼メールを送るケース）
この場合も本文で「皆様の貴重なお時間」と書いて、他の参加者への配慮を示す。

会社名が議事録から取れない場合の手がかり：
きんぼっとの話者ラベルに社名が含まれていることがある（例：「モノリスソフト山根」→ 株式会社モノリスソフト）。
ラベルが個人名のみなら推測せず空欄にして、確認事項に挙げる。

## 署名

締めの後に入れる。

```
ネオキャリア
[担当者名]
```

## 役職名の敬語

**役職名に「様」を付けない。** 「役員様」「取締役様」「部長様」は不自然な敬語になる。

- ○「役員の方」「取締役の方」「部長の方」
- ×「役員様」「取締役様」「部長様」

個人名に付ける場合は「様」でよい（例：「中居様」）。

## 次回打ち合わせ

```
URL：[担当者のZoom URL]
ミーティングID：[担当者のミーティングID]
```

担当者から聞いた値を使う。**他の担当者のZoom情報を流用しない。**
次回が対面訪問・別ツールの場合はこのブロックを入れない。
次回日程が未定なら、ブロックごと落とす。

## プラン体系（判定用・本文には書かない）

どのプランを提案したかで、サービス概要に書く機能が変わる。金額は本文に書かない。

| プラン | 機能 | 初期費用 | 月額 |
|---|---|---|---|
| スタンダード | 3Dバーチャル空間＋オフィスツアー＋AI面談 | 118万円 | 1万円 |
| ライト | 3Dバーチャル空間＋オフィスツアー（AI面談なし） | 78万円 | 1万円 |
| エントリー | AI面談のみ | 47万円 →キャンペーン23万円 | 1万円 |

- 直販の主力はエントリープラン。初期費用のキャンペーン価格が案内されることが多い
- 議事録に3D空間・オフィスツアーの説明が出ていればスタンダードまで提案している
- AI面談だけの説明ならエントリー。概要文でも3D空間に触れない

## サービス概要の書き方

型A・B・C・Eで使う。**固定するのは1文目だけ。** 残りは商談で出た話から書く。
定型文を並べると「どの会社にも送っている提案」に見えてしまい、
選ばれる力を上げるサービスの提案として矛盾する。

**1文目（固定）**

```
「どこでもオープンカンパニー」は、候補者が採用担当者に会う前の段階で、
貴社への志望度を高めるためのサービスです。
```

型Cのように既に説明済みの相手には「あらためてになりますが、」を頭に付ける。

**2文目以降（毎回書く）**

以下の3点を、その商談で実際に出た言葉を使って書く。3〜5行に収める。

1. **どの機能が、その会社の何に効くのか**
   提案したプランの機能に沿って書く（プラン体系の表を参照）。
   機能名を並べるのではなく「その会社の候補者に何が伝わるか」で書く。

2. **顧客が引っかかっていた点へのアンサー**
   商談で出た懸念・疑義に、この段落で答える。ここが一番効く部分。

3. **採用のどこに役立つか**
   母集団形成／応募前の志望度向上／選考の歩留まり改善のうち、
   **商談で話題になったものだけ**を書く。3つ並べない。

**書き分けの例**

同じサービスでも、商談内容によってこう変わる：

| 商談で出たこと | 概要パートで書くこと |
|---|---|
| 「社内撮影ができない」「情報の取り扱いが厳しい」 | AI面談で匿名の質問に答えられる点に寄せる。3D空間は触れるが深追いしない |
| 「学校訪問経由の紹介が減った」「マイナビで取れない」 | 母集団が構造的に増やしにくい前提で、来た人の志望度を上げる話に寄せる |
| 「イベントで着席はあるが次に繋がらない」 | イベント接点者が応募に進む後押しに寄せる。管理画面のデータ活用も足す |
| 「システムより自分の足で来る人と働きたい」 | 「代替ではなく会わせるための装置」という再定義に寄せる |

**やらないこと**

- 機能を網羅的に説明する（提案していないプランの機能を書く）
- 商談で話題にならなかった課題を「お役立ていただけます」と並べる
- 前回別の会社に送った概要文をそのまま流用する
